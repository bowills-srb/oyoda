Password reset + change-password flows + fix for Lanier's manual hash

Builds the self-service password reset flow so admins never have to
manually bcrypt-hash rows again. Also fixes a subtle bug where the
manual hash generated for Lanier earlier tonight won't verify at login.

CRITICAL FIX: Lanier's password hash
────────────────────────────────────
The app's verify_password() does SHA-256(password) → bcrypt, not raw
bcrypt. The one-liner I gave to hash Lanier's temp password used raw
bcrypt, so his hash won't match at login time. scripts/reset_lanier_
password.py regenerates his hash using the SAME function the app uses.
Before Lanier calls back, run:

    # Edit LANIER_EMAIL in the script first
    python scripts/reset_lanier_password.py

Once he's in, he should change his password via Settings → Change
Password (new in this commit).

SECURITY DETAILS
────────────────
- Reset tokens: 32 random bytes (secrets.token_urlsafe), stored as
  SHA-256 hash only. DB dump can't impersonate resets.
- Email enumeration: /forgot-password returns identical response for
  valid and invalid emails. Rate limit returns same response too.
- Token replay: used_at prevents re-use. Creating new token
  invalidates all prior unused ones for same operator.
- Expiry: 1 hour from creation. Validated on POST.
- Brute force: change-password failures hit the existing _record_failure
  rate limit (same as login attempts).
- Password rules: min 8, max 200 chars. Enforced client + server.
